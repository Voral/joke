# Файловая система

`Vasoft\Joke\Support\FileSystem` — это сервис для безопасной работы с файлами и директориями в рамках базового пути
проекта. Он гарантирует, что все операции чтения, записи и подключения файлов выполняются **только внутри разрешённой
директории**, защищая приложение от атак типа directory traversal и symlink-переходов.

Сервис является **неизменяемым** (immutable) после создания и регистрируется в DI-контейнере как синглтон.

---

## Зачем нужен FileSystem?

Прямое использование `include`, `file_get_contents`, `file_put_contents` в контроллерах и сервисах создаёт несколько
проблем:

1. **Уязвимость к path traversal.** Конструкция `include $_GET['page'] . '.php'` позволяет злоумышленнику прочитать
   произвольный файл на сервере через `../../etc/passwd`.
2. **Утечка скоупа при `include`.** Локальные переменные вызывающего метода становятся доступны в подключаемом файле,
   что приводит к трудноотлаживаемым конфликтам имён.
3. **Отсутствие единого контракта.** Каждый компонент сам решает, как формировать пути, где хранить кэш и как писать
   файлы. Это нарушает принцип единственной ответственности.

`FileSystem` решает все три проблемы: валидирует каждый путь относительно `basePath`, изолирует скоуп подключаемых
файлов через Closure и предоставляет единый API для всех файловых операций.

После регистрации сервис доступен через автовайринг в любом контроллере или другом сервисе:

```php
class CacheController
{
    public function __construct(private readonly FileSystem $fs) {}
}
```

## Базовый путь и стандартные директории

Все операции `FileSystem` привязаны к `basePath` — абсолютному пути к корню проекта. Сервис предоставляет property hooks
для быстрого доступа к стандартным директориям:

| Свойство         | Путь                         | Назначение                                      |
|:-----------------|:-----------------------------|:------------------------------------------------|
| `$basePath`      | `/var/www/my-app/`           | Корень проекта                                  |
| `$bootstrapPath` | `/var/www/my-app/bootstrap/` | Скрипты инициализации (`app.php`, `kernel.php`) |
| `$publicPath`    | `/var/www/my-app/public/`    | Точка входа веб-сервера, статические ресурсы    |
| `$varPath`       | `/var/www/my-app/var/`       | Служебные данные (кэш, логи)                    |
| `$cachePath`     | `/var/www/my-app/var/cache/` | Скомпилированные шаблоны, кэш конфигурации      |
| `$logPath`       | `/var/www/my-app/var/log/`   | Файлы журналов событий и ошибок                 |

> Все пути автоматически заканчиваются разделителем директории.

## Формирование путей

### Методы `at*()`

Для построения абсолютных путей относительно стандартных директорий используются методы `at*()`:

```php
$fs->atBase('config/app.php');       // /var/www/my-app/config/app.php
$fs->atCache('routes.cache');        // /var/www/my-app/var/cache/routes.cache
$fs->atLog('error.log');             // /var/www/my-app/var/log/error.log
$fs->atBootstrap('kernel.php');      // /var/www/my-app/bootstrap/kernel.php
$fs->atVar('sessions/abc123');       // /var/www/my-app/var/sessions/abc123
```

### Универсальный метод `at()`

Для произвольной директории:

```php
$fs->at('/tmp/uploads', 'avatar.png');  // /tmp/uploads/avatar.png
```

Метод нормализует переданную директорию через `normalizeDir()` и добавляет к ней относительный путь.

### Нормализация

| Метод             | Вход               | Результат                        | Особенность                            |
|:------------------|:-------------------|:---------------------------------|:---------------------------------------|
| `normalizeDir()`  | `'config'`         | `/var/www/my-app/config/`        | Всегда завершается разделителем        |
| `normalizeFile()` | `'config/app.php'` | `/var/www/my-app/config/app.php` | Без завершающего разделителя           |
| `isAbsolute()`    | `'/etc/passwd'`    | `true`                           | Учитывает Windows (`C:\`) и Unix (`/`) |

## Валидация путей

Каждая операция в `FileSystem` начинается с вызова `validatePath()`. Метод выполняет **двухуровневую проверку**:

### 1. Логическая нормализация

Путь очищается от конструкций `..` и `.` без обращения к файловой системе. Если результат не начинается с `basePath` —
выбрасывается `FileSystemException`.

```php
$fs->readFile($fs->atBase('../../../etc/passwd'));
// → FileSystemException: Path must be in base path
```

### 2. Проверка через `realpath()`

Если файл физически существует на диске, дополнительно вызывается `realpath()` для разрешения символических ссылок.
Если реальное расположение файла выходит за пределы `basePath` — выбрасывается исключение.

```
/var/www/my-app/public/link → /etc/passwd   ← symlink-атака заблокирована
```

> Двухуровневая проверка защищает как от логических атак (`../../`), так и от физических (symlink за пределами базы).

## Подключение файлов

Это ключевая особенность сервиса. Методы подключения используют **Closure для изоляции области видимости** — в
подключаемый файл попадают только те переменные, которые переданы явно.

### Почему Closure?

Обычный `include` внутри метода делает доступными в подключаемом файле все локальные переменные этого метода (`$file`,
`$this`, `$vars` и т.д.). Closure создаёт чистый скоуп:

```php
$includer = static function (string $__path, array $__vars, IncludeType $__type): mixed {
    extract($__vars, EXTR_SKIP);
    unset($__vars);

    return match ($__type) {
        IncludeType::INCLUDE      => include $__path,
        IncludeType::INCLUDE_ONCE => include_once $__path,
        IncludeType::REQUIRE      => require $__path,
        IncludeType::REQUIRE_ONCE => require_once $__path,
    };
};
```

Флаг `EXTR_SKIP` гарантирует, что переданные переменные не перезапишут служебные (`$__path`, `$__type`).

### Возвращаемые значения

Конструкции `include` и `require` возвращают значение из `return` подключаемого файла. Это позволяет использовать
сервис как для шаблонов (вывод через `echo`), так и для конфигов (возврат массива):

```php
// config/app.php содержит: return ['debug' => true, 'locale' => 'ru'];
$config = $fs->requireFile($fs->atBase('config/app.php'));
// $config === ['debug' => true, 'locale' => 'ru']
```

Если подключаемый файл не содержит явного `return` — возвращается `1` (стандартное поведение PHP).
Если файл не найден и использован `include` (не `require`) — возвращается `false`.

### Типы подключения (`IncludeType`)

Языковые конструкции `include`, `require` и их `_once`-варианты невозможно передать как параметр функции. Для решения
этой проблемы используется backed-enum `Vasoft\Joke\Support\IncludeType`:

| Case           | Значение         | Поведение при отсутствии файла  | Возвращаемое значение |
|:---------------|:-----------------|:--------------------------------|:----------------------|
| `INCLUDE`      | `'include'`      | Тихий пропуск (warning)         | `false`               |
| `INCLUDE_ONCE` | `'include_once'` | Тихий пропуск, один раз         | `false`               |
| `REQUIRE`      | `'require'`      | `FileSystemException`           | —                     |
| `REQUIRE_ONCE` | `'require_once'` | `FileSystemException`, один раз | —                     |

### Публичные методы

| Метод               | Аналог PHP     | Ошибка при отсутствии файла | Кастомное сообщение | Возвращает |
|:--------------------|:---------------|:----------------------------|:--------------------|:-----------|
| `includeFile()`     | `include`      | Нет                         | —                   | `mixed`    |
| `requireFile()`     | `require`      | Да                          | ✅ `$errorMessage`   | `mixed`    |
| `includeFileOnce()` | `include_once` | Нет                         | —                   | `mixed`    |
| `requireFileOnce()` | `require_once` | Да                          | ✅ `$errorMessage`   | `mixed`    |

### Примеры

#### Передача переменных в шаблон

```php
$html = $this->renderView('welcome.php', [
    'title' => 'Добро пожаловать',
    'user'  => $currentUser,
]);

private function renderView(string $template, array $data): string
{
    ob_start();
    $this->fs->includeFile($this->fs->atBase('views/' . $template), $data);
    return ob_get_clean();
}
```

Внутри `views/welcome.php` доступны **только** `$title` и `$user`. Переменные `$this`, `$template`, `$data` из
вызывающего метода недоступны.

#### Подключение конфигурации

```php
$config = $fs->requireFile($fs->atBase('config/app.php'), [
    'env' => $environment,
]);
```

#### Кастомное сообщение об ошибке

```php
$this->fs->requireFile(
    $this->fs->atBootstrap('kernel.php'),
    [],
    'Файл ядра приложения не найден. Запустите composer install.'
);
```

## Чтение и запись файлов

### Чтение

```php
$content = $fs->readFile($fs->atBase('config/app.php'));

$chunk = $fs->readFile($fs->atLog('app.log'), offset: 1024, length: 512);
```

### Обычная запись

```php
$bytes = $fs->writeFile($fs->atCache('data.json'), json_encode($data));
```

### Атомарная запись (`writeFileSafe`)

Запись через временный файл с последующим `rename()`. Гарантирует, что целевой файл никогда не окажется в частично
записанном состоянии:

```php
$fs->writeFileSafe($fs->atCache('routes.cache'), $serializedRoutes);
```

Алгоритм:

1. Создаётся временный файл рядом с целевым (`tempnam()`),
2. Данные записываются во временный файл,
3. Выполняется атомарный `rename()` временного файла в целевой,
4. При ошибке на любом этапе — временный файл удаляется.

> Используйте `writeFileSafe()` для кэша, конфигураций и любых файлов, целостность которых критична.
> Обычный `writeFile()` подходит для логов и некритичных данных.

## Создание директорий

```php
$fs->ensureDirectory($fs->atCache('compiled'));

$fs->ensureDirectory($fs->atVar('uploads'), 0o755);
```

Метод работает рекурсивно (аналог `mkdir -p`). Если директория уже существует — ничего не происходит. Перед созданием
выполняется `validatePath()`.

## Обработка ошибок

| Исключение            | Когда выбрасывается                                               |
|:----------------------|:------------------------------------------------------------------|
| `ConfigException`     | `basePath` не существует или не является директорией              |
| `FileSystemException` | Путь вне `basePath`, symlink-атака, ошибка чтения/записи/создания |

## Лучшие практики

1. **Всегда используйте `at*()` для формирования путей.** Не конкатенируйте строки вручную — это обходит нормализацию
   и может привести к уязвимостям.
2. **Используйте `writeFileSafe()` для кэша.** Частично записанный кэш-файл может сломать приложение при следующем
   запросе.
3. **Передавайте переменные через `$vars`, а не через глобальные состояния.** Closure-изоляция работает только с
   явно переданным массивом.
4. **Не используйте `includeFile()` для критичных файлов.** Если отсутствие файла должно остановить выполнение —
   используйте `requireFile()` или `requireFileOnce()`.
5. **Ключи массива `$vars` должны быть валидными именами переменных PHP.** Ключи вроде `my-var` или `0name` будут
   проигнорированы `extract()` без предупреждения.

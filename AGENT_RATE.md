# Оценка решений задачи ограничителя запросов агентами

## GigaCode

### Не понравилось

- Для определения путей к конфигам создал хелпер, вместо обращения к предназначенного для этого сервису
- Сразу заморозил конфиг, хотя по идее фреймворка это происходит в определенный момент логики фреймворка
- Документацию положил в корень документации, а не подобрал подходящий уровень
- Класс исключения разместил в контрактах (не как "обычно" в фреймворке), и копию этого же класса в пространстве имен
  хранилищ
- Интерфейс ограничителя разместил в пространстве имен сервиса хранилища
- При создании провайдера нарушил условия интерфейса
- Есть обращения к несуществующим методам контейнера
- Один из интерфейсов разместил не в пространстве контрактов
- Не точно соблюдает стиль кода и требования на минимальную версию PHP (не использует новые возможности)
- Не добавил статус ответа в enum, но использует его как существующий
- Хранилище в массиве реализовал в основном пространстве имен, хотя оно по сути имеет смысл только в тестах
- Некорректные примеры в документации
- Судя по всему реальная конфигурация для отдельных маршрутов только через настройки в общем конфиге. В конфиге есть для
  этого метод, но в коде не используется лимиты маршрутов из конфига
- При создании JsonResponse в конструктор передал два дополнительных параметра, что по идее вообще должно было вызвать падение важного теста - тесты не проверяют, что в случае блокировки выдан код 429
- Мидлвар при блокировке выдает всегда Json ответ, хотя по идеологии фреймворка должен быть тип тот же, что и при нормальном ответе
- Попытка перезаписать свойство только для чтения

тестов, начал ломать свой код.
